# 应用架构

更新于 2026-10-18，版本 1.0.2。Windows x64 首发，其他平台需单独构建验收。

## 层次

Tauri 2 提供窗口和系统服务；React/TypeScript 展示数据及交互；独立 Rust hm-core 校验业务、管理 SQLite 与材料文件。界面通过类型化 IPC 调用 Rust，不直接执行 SQL。开发预览仅在开发构建且显式 preview=1 时启用，生产构建不含内存业务适配器。

src/features 按 cases、calendar、materials、contacts、finance、settings 划分；components 放共用弹窗、搜索、通知与回收站。src-tauri 的 commands.rs 处理业务命令，files.rs 负责原生文件入口，desktop.rs 负责托盘、通知、自启动和升级。

## 数据与文件

案件 → 办理程序 → 阶段。程序切换不覆盖历史，阶段结束不自动结案。状态移动只更新状态字段；稳定 UUID 与数据库事务保证建案重试不重复，默认程序和阶段同事务创建。自定义状态删除要求为空。

SQLite 外键、WAL、FULL 同步、5 秒 busy timeout，user_version 当前为 4。迁移在事务内执行；旧版本 1/2 在迁移前用 SQLite 在线备份 API 保存数据库副本。更高版本拒绝打开。

003_v1_workspace.sql 增加材料、对象/案件身份、阶段、事件、整数分收支、案件补充信息、设置、提醒送达去重。工作记录和材料支持软删除，彻底删除须明确确认；案件删除不删除独立对象。全局名称搜索在已有工作区数据上按类型匹配，不搜索材料正文。

材料由 Rust 复制到 UUID 对象目录，文件夹是虚拟层次；同名自动编号。程序、文件夹、记录、凭证都校验所属案件；移动防循环，导出禁止覆盖工作区，文件路径检查规范路径与符号链接边界。系统打开管理副本，支持外部应用保存。录音仅显式点击启动，原始字节通过 IPC 归档；中文名称的请求头以 ASCII JSON 编码。

PDF.js 懒加载，worker、字体、CMap、WASM 随应用离线打包。预览通过运行时精确授权的 asset scope 读取管理文件，CSP 限制远程内容。Windows 生产主窗口使用 HTTPS 自定义协议，以支持安全上下文中的麦克风。

## 日程与后台

保留已认可的日/周/月布局、半小时默认时长、暗蓝卡片与细边。日程默认不关联案件，用户通过加号主动选择。墙上时间不转 UTC：全天含结束日，定时结束不含端点；重叠并排，跨日分片。当前时间线按分钟刷新，窗口恢复刷新，不抢手动滚动。

提醒持久化时间与送达键，后台每分钟检查一次；启动/恢复时补提醒最近 24 小时。全天按上午 9 点，未设置不提醒。系统成功发送后标记送达；托盘退出停止后台任务。通知中心列出到期与即将提醒的安排。自启动仅用户选择后启用。

## 备份与恢复

备份使用 SQLite backup API 获取一致快照，再复制当前引用的材料、录音（含回收站），生成 SHA-256 清单；每天自动一次，默认保留 7 份，也可手动。目录失效反馈到设置，不静默伪装成功。

恢复先验证全部哈希、数据库完整性/外键/版本及材料引用，再保留恢复前完整副本，写入并同步恢复日志。材料使用独立代际目录，数据库恢复后切换内部路径设置，避免 WebView 或外部 Office 占用旧文件时无法替换。成功移除日志；中断时下次启动依据日志恢复安全副本。旧代际暂留，当前备份不包含未引用代际。Windows 临时共享占用只在暂存目录改名时做有限重试，失败仍报告。

安装版数据由 Tauri app_local_data_dir 确定，通常为 %LOCALAPPDATA%\com.limushu.hm。历史 .portable 标记保留兼容，但 1.0 默认发布安装包，彼此数据不混用。设置显示真实数据位置。

## 安装与更新

NSIS 当前用户安装；Tauri updater 从 GitHub Release 的 latest.json 检查版本。用户确认后先完整备份、下载并验证内置公钥对应的签名，再启动升级。私钥在仓库外或 GitHub Actions secret，不进软件；Windows 发布者证书尚未配置。发布步骤见[发布流程](releasing.md)。

## 验证与延后范围

核心测试独立于窗口；界面测试使用明确内存预览；原生测试仅新建隔离虚构数据目录，验证文件、PDF、录音、SQLite 备份恢复与重启。验收范围与限制见[使用说明](v1.0-acceptance.md)。

移动端、macOS、云同步、协作、AI、全文检索、转写、重复日程、法定期限自动计算不作为此版本已验收能力。保留 DESIGN-NOTION-COLOR 与 DESIGN-NOTION-DETAIL 后续打磨。

1.0.2：contact_relations 保存法官/法院关系，程序参与对象通过 contact_links 关联，显示名称随引用更新；搜索选择器替代法院和法官自由文本录入。关系图从真实案件/程序/对象边生成，不把案件的每个法院都直接混成一层。恢复版本 3 的完整备份时自动执行迁移 4，详见[对象关系优化](relationship-design.md)。
