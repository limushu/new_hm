## 目标与优先级

用户希望进入详情后，先了解案件整体进度和当前最重要的事情，再轻松录音、创建文档、查找历史材料，同时掌握相关人物与机构。

优先级：案件脉络与当前重点 → 就地处理工作 → 人物及材料关系 → 完整档案与管理功能。

首屏验收目标：五秒内辨认当前流程/阶段、最近的重要变化、当前需要关注的一件事。首屏不展开所有模块、编辑字段和空态。

## 页面组织

案件身份使用紧凑标题、状态和当前关注流程摘要。顶部分区为「脉络」「材料」「相关人」；案件资料、费用及管理功能可从稳定的「更多」入口进入。重要的费用事项仍可由用户置顶到当前重点，不以入口位置限制其重要性。

「脉络」为默认页：

1. 紧凑的当前进度：显示已确认里程碑、当前阶段和已录入的下一节点，不展示推算的案件完成百分比。多个并行流程显示数量及可展开摘要，不强行排成单线。
2. 当前重点：优先显示用户置顶事项，其次是按已录入日期识别的临近或逾期事项。显示突出原因和直接处理入口，首屏突出一项，其余折叠。没有设置重点与“没有风险”分别表达。
3. 案件时间轴：默认显示关键节点，近期在上；能查看全部、按流程或类型筛选。进入节点或关联资源后返回，保留时间轴位置和筛选。
4. 固定操作栏：「录音」「创建」「查找」。在案件详情内保持稳定位置，不与应用主导航堆成两排底栏；退出案件后回到应用主导航。

手机纵向阅读；桌面和宽平板使用中间时间轴、右侧当前重点及关键人物摘要，完整人物关系按需展开。两端共用同一事件与关联数据。

## 时间轴表达什么

时间轴围绕发生的事情组织，区别于数据库操作日志。事实事件、办理节点、沟通、材料提交/接收、用户标记的重要事项均可成为节点；普通修改、自动保存、批量上传的技术操作不逐条挤进默认脉络。

需要区分两种阅读目的：「案情事实」解释借款、履行、沟通等事情何时发生；「办理进展」解释委托、准备材料、立案、庭审等工作如何推进。默认展示用户确认的重要脉络，通过筛选查看两种视角，保留共同时间坐标及相互引用。高保真首屏示范的是近期办理节点，较早案情事实在展开完整脉络后继续阅读，不能让文件上传记录替代案情分析。

每个节点包含：

- 标题与简短说明；类型图标和文字标签共同表达含义。
- 发生日期/时间与精度；日期不明时允许未确认或区间，不强制补造精确时间。
- 所属流程和可选阶段。
- 相关人物/机构及其在这件事中的角色。
- 文件、图片、录音或文档的稳定引用。
- 可选的后续待办、截止日期及等待事项。

发生时间与录入时间分别保存。后来导入旧文件，不能将上传日期冒充文件记载的事实发生日期。旧数据若只有创建或导入时间，明确显示“记录于/归档于”，由用户确认后才能作为事实日期。

事实节点允许标注来源与「待核实」，也可记录不同主体的不同说法；关联一份证据不自动表示事实已被确认。图中的完成勾选用于已完成的办理节点，不代替对事实真伪的判断。

已发生的事件使用实线节点；计划安排使用虚线与「计划」文字，放在明确分隔的后续安排区域。待办完成、阶段完成、流程办结、案件结案是不同事实，不相互自动推断。

节点卡片默认只有日期、标题、两行摘要及少量人物/附件提示。点开后才展示完整说明、所有相关人、材料预览与后续工作。重要事实可手动置顶；信息来源和更新时间可查。

## 操作与上下文

固定栏的一次点击打开录音面板，用户点击「开始」后才访问麦克风。录音显示案件及可选节点归属、时长、暂停/继续与结束保存。后台、锁屏和系统中断的暂停行为沿用现有能力；操作文件选择器等场景须正确处理暂停并保留草稿。

「创建」提供少量清楚的选项：记录进展、空白文档、待办、日程。文档从空白或已有模板开始，先作为本机草稿自动保存；用户确认关联后出现在材料和对应事件中。自动保存本身不反复生成时间轴节点。

「查找」默认搜索本案全部历史文档、材料和录音，显示名称、类型、日期及关联事件。按人物、流程或阶段筛选是显式操作，并允许一键回到全案。查找并打开历史材料后，能返回原来的工作位置。

从某一节点内创建内容时，预填本案、节点及相应流程，保存前清楚展示并允许调整。从全局固定栏操作时，不把刚浏览的某个人或隐藏的筛选静默当成新内容归属。

一次「记录进展」可以包含文字、关联人物、录音/文件及可选下一步，减少反复退出再关联。用户可以只记录一句话，不强迫补齐结构。

## 人物与机构

人物关系不能仅是通讯录列表。详情需要同时回答：此人是谁、与本案是什么关系、属于哪个流程、参与过什么、如何联系。

- 人物与机构分开建模和展示，法院属于机构，法官属于人物。
- 区分我方当事人、对方当事人、双方代理律师、法官及其他相关人。
- 角色与具体案件、流程及必要的时间范围关联；同一个人可在不同流程承担不同角色，不以全局永久标签覆盖历史。
- 默认呈现少量关键人物及审理机构；完整关系图按需展开，角色分组列表作为同等可用的查找方式。
- 图中人物用圆形头像/姓名缩写，机构用建筑图标；连线标注「委托」「代理」「承办」等关系，不能只靠颜色猜含义。
- 人物详情连接其参与的时间轴事件、关联材料和联系方式。真实头像可选，缺省使用姓名缩写，不自动制造人物照片。

人物/法院信息是否位于首屏摘要，由用户对案件的实际需要决定；图谱不强行占据全部首屏空间。

## 图文配合与高保真图构成

采用浅色纸张背景、深色正文、案笺现有蓝色操作语义，搭配克制的青绿与琥珀状态色。保留深色主题的后续映射。主要阅读内容保持现有 15px 语义尺寸；手机触摸目标至少 44px。先减少首屏内容，再安排字号和留白。

图形承担信息表达：文件显示真实缩略图或类型图标，录音显示波形和时长，人物显示头像与角色，进度显示节点状态与文字。图片加载失败保留可读文件名和类型，不以图片作为唯一入口。

本次高保真主图采用三个手机界面并列：

1. 「案件脉络」：当前进度、重点事项、带人物及附件的时间轴，以及固定操作栏。
2. 「快速记录」：同一案件上下文内的记录、录音与文档关联，保存后回到脉络。
3. 「相关人」：关键人物、法院机构、轻量关系图和可操作的人物卡片。

所有人物、案件、机构、文件和日期均为虚构示例。图稿为目标界面，不用作当前上架版本的真实截图。

## 实现边界与验收

当前系统已有案件、流程、阶段、待办、日程、材料、工作记录、人物关系和原生录音/文件驱动。结构化案件脉络、事实日期与录入日期区分、重点置顶及应用内新建文档，需要补充设计与实现，不能仅靠重排现有组件宣布完成。

实现时保持材料单份存储、稳定 ID 与多处引用；节点引用材料不复制原文件。新节点、关联、录音及文档保存需要处理失败、取消、重复提交及草稿恢复，避免出现空节点、重复材料或失去关联的录音。

先验证三条完整路径：

1. 打开案件 → 看懂进度和当前重点 → 点进某一事件 → 找到相关人和依据材料 → 返回原位置。
2. 从详情唤出录音 → 明确开始 → 暂停/结束 → 保存并关联 → 时间轴与材料库显示同一份内容。
3. 新建文档或查找旧文件 → 编辑/查看 → 关联到当前事件 → 后续可从人物、事件或材料入口再次找到。

通过原型验证信息层级和路径，再确定事件模型、旧数据兼容与平台能力接入；新设计不直接替换正在审核的安装包。
