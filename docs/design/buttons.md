# 按钮规范

同级操作共用 [Button](../../src/components/Button.tsx)，尺寸及颜色由 [buttons.css](../../src/components/buttons.css) 统一定义。页面只负责位置、排列和响应式换行，不另写按钮字号、圆角、内边距或强调色。

| 属性 | 规格 |
| --- | --- |
| 高度 | 44px |
| 字体 | `--text-base`（14px），500 字重，20px 行高 |
| 图标 | 18px，文字左侧，间距 8px |
| 圆角 | 8px |
| 内边距 | 水平 14px，垂直居中 |
| 边框 | 1px；无边框样式使用透明色，避免尺寸变化 |
| 宽度 | 随文字内容；移动端同样规格，不为单个页面缩小或任意拉宽 |

主操作使用 `variant="primary"`，背景与悬停态来自自适应主题的 `--primary`、`--primary-hover`，文字使用 `--on-primary`。次要操作使用 `secondary`，辅助操作使用 `ghost`，确认删除使用 `danger`。这些变体共用尺寸与排版。

页面新建入口统一写「新建 + 对象名称」：新建日程、新建案件、新建对象，使用相同加号图标。导入存量文件使用「添加材料」，保存表单使用「保存」或「保存日程」等明确动作。图标不可代替必要的名称；纯图标控制仍需可访问名称。

全局日程、案件、联系对象入口，以及录音、材料、设置和弹窗确认操作复用此规范。表单底部可换行，不能通过缩小某个按钮来挤进窄屏。桌面状态列的整行新建入口可以铺满列宽，尺寸与字体仍沿用组件。筛选标签、页签、对象卡片与底部导航各有其内容结构，不作为主操作按钮套用。

核对时在同一设备、同一主题下比较实际计算尺寸，并检查深浅主题、320/390/430px 窄屏及桌面：文案完整、图标对齐、无横向溢出，保存与取消仍有明确行为。已有流程回归验证交互；浏览器截图不替代 iOS 真机验收或审核视频。
