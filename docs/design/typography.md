# 字体映射规范

## 字体族

应用 UI 统一使用 styles.css 中 --font-ui：-apple-system、BlinkMacSystemFont、Segoe UI、Microsoft YaHei UI、PingFang SC、Microsoft YaHei、system-ui、sans-serif，按平台可用字体依次回退。Windows 拉丁字符通常使用 Segoe UI，中文使用 Microsoft YaHei UI；macOS 中文使用 PingFang SC。统一原则是同一平台下相同内容角色一致，而非强制所有平台加载同一个外部字体。

按钮、输入框、下拉框、弹层、日期选择器、SVG 图内文字继承同一字体族，不让原生控件落回另一套字体。font-synthesis: none 避免浏览器制造伪粗体。无需联网下载字体，保持离线可用。

## 语义尺寸

所有应用 CSS 引用全局变量，不在组件中另写任意字号。根变量定义是像素值的唯一来源。

| 变量 | 大小 | 用途 |
| --- | --- | --- |
| --text-xs | 12px | 紧凑数量、徽标、时间轴与图表刻度 |
| --text-sm | 13px | 字段名、表头、日期、大小和辅助信息 |
| --text-base | 14px | 导航、按钮、输入、属性与常规界面 |
| --text-body | 15px | 文件名、阅读正文和主要内容 |
| --text-heading | 18px | 功能分区标题 |
| --text-title-sm | 20px | 当前流程摘要、统计数字 |
| --text-title | 24px | 局部页面标题 |
| --text-display-mobile | 24px | 窄屏案件标题 |
| --text-display | 30px | 宽屏案件标题 |

1.3.2 重新平衡阅读与操作的比例，替代 1.3.1 中全部正文和操作最小 16px 的硬性规则。14px 用于操作，15px 用于主要阅读内容，13px 用于元信息，12px 只用于紧凑标记和刻度。文字靠清晰对比和合适行距保持可读，而非统一放大。窄屏不再缩小正文，优先换行、改变工具栏布局或隐藏次要列。

先处理布局中的重复内容，再决定字号；不能把空间问题简单归因于字号。检查 Windows 实际 DPI 下的整体效果，浏览器缩放不能替代原生验收。

## 字重、行距与图标

正文使用 400，强调、选中项使用 500，标题使用 600。避免 550 等缺乏跨平台一致性的中间字重。正文默认行高 1.5；标题和紧凑按钮可按现有组件使用更紧的行高，禁止用固定高度裁掉中文基线。

使用 --weight-regular / --weight-medium / --weight-strong 明确 400 / 500 / 600 的映射。案件功能分区标题统一为 --text-heading（18px）、600；主要阅读内容为 15px，操作和属性为 14px，元信息为 13px。常规图标统一 --icon-stroke（1.7）和 --icon-muted，属性图标为 13px；案件页书页标识使用独立的柔和双色，HM 品牌独立于正文图标。

1.1.4 明确文字颜色按内容角色映射，不按字号或所在行是否次要来变灰：

| 内容角色 | 颜色变量 | 规则 |
| --- | --- | --- |
| 标题、正文、待办内容、备注、已填写属性值、实际日期及记录 | --text / --text-strong（同为 #ececea） | 标题靠字号和字重建立层级，正文保持同等清晰；输入、Select 和弹层不继承字段名的灰色 |
| 属性名、辅助说明、帮助入口、图标 | --muted / --icon-muted | 辅助识别，不覆盖对应属性值 |
| 占位、未填写、无内容提示 | --quiet | 输入框 placeholder、未指定的阶段和前序程序明确区别于真实内容 |
| 已完成、跳过、禁用、状态与危险操作 | 对应状态色或禁用规则 | 状态色保留语义，不把所有颜色统一刷白 |

案件页面默认只保留简短空态，不重复讲解“点击节点”“关联后显示”等操作；复杂阶段规则通过折叠帮助查看。删除影响、未保存错误、历史对象映射等会影响决定的信息仍按需呈现。

参考 Notion 的信息层级，不照搬参考图的截图缩放比例：宽侧页以书页标识、标题和紧凑属性建立开头，600px 以内收成行内标识与标题；概览功能保持逐行排列，主要用间距组织，保留关键分隔线而非每一段都画框。

金额、时间、日期和统计数使用 font-variant-numeric: tabular-nums，以便对齐。图表中的金额与账目共用金额格式化，不在图中省略影响理解的单位。默认界面图标使用同一 Lucide 线性图标族，常规 16px，辅助 12–14px；品牌标志使用独立 SVG，不把 emoji 混作功能图标。

## 检查方式

检查案件标题、案号输入、Select 弹层、DateField、侧栏、联系对象及 SVG 图表的 computed font-family；Windows 原生 WebView2 再用 CDP 检查中文实际渲染字体。确认日期和数字没有使用另一套系统原生控件字体。

不改写用户材料本身的排版：PDF、图片、导入文档的预览保持原文件字体与内容。历史 HTML 设计原型不是应用 CSS 的规范来源。

## 1.3 主导航与双主题

案件的概览、材料、流程详情、收支为一级页签，位于案件属性之后、办理路径之前，滚动时保持可见。四项共用 text-base、weight-medium、同一行高，选中项仅改变底色、图标和文字颜色，不改变字号或字重。窄侧页四项一同使用 text-base，不单独缩小某项；方向键、Home、End 可切换。

普通正文、日期与已填写字段统一使用 text；辅助标签使用 muted，空值使用 quiet。主题切换不改变字体族、字号或布局。页面分区用小面积蓝、青、紫、琥珀色图标区分，标题仍为中性正文色。新增图标沿用 Lucide，不混用 emoji。

颜色角色集中在 themes.css：背景层级、正文、辅助文字、边框、强调色、语义色及对应弱底色，深浅两套分别配置。不得通过反相滤镜实现浅色，也不为各页单独保留深色硬编码。PDF 等材料原本的白纸和文档内容保持原样。Windows 主题同步到窗口；主题偏好写入工作区设置，启动缓存只保存外观选择。

## 1.3.2 页面密度与材料阅读顺序

案件页头采用行内书页图标与标题；状态和标签为紧凑行内属性，缩短可见标签，输入的无障碍名称保留完整业务语义。案件名称是唯一的主视觉焦点，导航保持 14px 同字号，不与标题竞争。

四个功能页签 → 案件共用/各流程范围 → 搜索及文件操作 → 文件列表。已选中的“材料”页签表达当前功能，不再重复一个材料标题；当前范围由选中项表达，根目录不再另占一行重复名称。进入文件夹或搜索后才出现可点击路径与项目数。添加按钮的悬停文字始终显示完整目标，上传、录音、文件夹和原生拖入仍沿用当前目标。

文件名 15px、操作与路径 14px、日期/大小/表头 13px，文件行常规 44px。实际数据和备注保持正文色；表头、数量、搜索占位和空态使用辅助色。深浅两套主题共用字号与布局规则。

工具栏按实际侧页宽度适配：440px 以内搜索独立一行；600px 以内隐藏日期列，保留文件名和大小；更宽时使用单行工具栏。不因窗口小而缩小正文。800×600 桌面验收要求首屏完整可见至少四行普通短名称材料；长文件名允许自然换行。

## 1.4 工作空间的层次

页签统一“概况 / 材料 / 办理 / 费用”，仍为 14px、500。流程关系只在办理中按需展开。阶段的选中样式表达浏览，当前办理以明确文字标识，不能让两种蓝色选框混淆状态。任务和结果 15px、操作 14px、日期/用途 13px；实际内容保持正文色，等待事项用琥珀色，空值才弱化。

单流程取消重复导航卡片，流程资料与历史折叠；小屏按案件容器宽度换行，不缩小字体。材料仍满足 800×600 首屏四行常规材料；全案默认不额外重复“范围：全案”，已有全案材料选中项表达范围。跨阶段引用和筛选规则见[工作空间规格](case-workspace.md)。

## 1.4.1 状态与图形界面

状态默认色由 statusPalette 映射：未开始中性灰、进行中蓝、已结案绿。看板与详情状态共用底色、文字和圆点，深浅主题分别定义 token；用户自选颜色保持不变。状态保留可输入、联想和创建行为，不改变业务含义。

办理分区的常用新增动作使用柔和蓝底，关联与模板操作用中性细边框和图标，不把所有操作都画成蓝色链接。维持 1.3.2 已确认的字号与间距比例。关系图节点文字使用 --text-base，关联列表使用标准正文与元信息比例；空间不足时避让名称或缩放探索，不一律缩小字体。

1.4.2 修正欢迎展示条件：新用户和已有工作区升级后均可看到一次 HM 欢迎动画。1.4.1 的旧 true 标记包含自动跳过，不视为真正看过。只有实际点击开始、跳过或按 Escape 并保存成功，才将 SQLite 的 onboarding_done 记为 hm-welcome-1；该欢迎内容标识在后续软件版本中保持稳定，避免每次更新重复展示。设置 → 外观可重播。动画不创建或修改案件记录，遵循 prefers-reduced-motion，按钮立即可操作；保存失败保留重试入口。
