# 案件系统与扩展接口

状态：1.5.0 第一阶段框架。一个案件作为工作空间，时间轴、关系、账目和材料是同一批资源的不同视图。本文区分已接入能力与尚未实现的扩展服务。

## 边界与目录

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 领域与持久化 | `crates/hm-core/src/case_system/` | 稳定引用、重要程度、标签、案件关联、归属校验、事务与生命周期 |
| 应用装配 | `crates/hm-application/src/case_system.rs` | 通过可注入的原生资源解析器执行用例 |
| IPC | `src-tauri/src/ipc/case_system.rs` | 调用原生用例，沿用工作区锁与类型化错误 |
| 视图契约与注册 | `src/case-system/` | 模块、时间轴投影、组合筛选、资源查找及扩展服务接口 |
| 界面适配 | `src/features/cases/resourcePresentations.tsx` | 为不同资源注册详情及编辑器，复用原有收支、待办、日程和材料能力 |
| 共享界面 | `CaseTimeline.tsx`、`ResourceSettings.tsx` | 时间轴、筛选、重要程度、标签与双向关联 |

文件系统、录音和系统选择器继续使用既有 Rust/原生驱动。前端注册表只投影工作区快照与路由编辑界面，不直接写数据库或文件。开发预览仍为显式启用的内存适配器。

## 统一引用，保留各自实体

`ResourceRef { kind, id }` 标识资源。`kind` 是稳定、不翻译的代码；`id` 是拥有模块的资源 ID。案件、流程、事件、记录、待办、材料、账目、当事人和全局联系对象沿用原记录，没有复制成第二套时间轴数据库。

`ResourceMetadata` 按案件和引用保存重要程度及标签；重要程度、类型、标签独立。`ResourceRelation` 保存同案资源之间有方向的关联，关系代码与用户填写的具体含义分别保存。人物、机构、部门可建立代理、隶属等关系，并进入本案关系图。

原生每次保存都检查案件有效、资源存在及归属。联系对象目录为全局共享，可通过明确的本案关联加入案件；其他案件的材料、当事人、账目等不能跨案关联。稳定关联 ID 支持重试，禁止将已有 ID 转移到另一案件。硬删除清理引用；软删除保留信息以便恢复；资源所属案件改变时解除原案件注释及关联。

## 时间轴与账目

内置模块为进展、工作记录、材料/文书/录音、收支、待办和日程。各模块返回统一 `TimelineEntry`，引擎合并注释及关联，按日期排序、分页显示。日期保留发生、记录、归档、收支、计划或截止含义。缺失日期不推断，完成待办不伪造完成时间，未来归档时间不自动成为计划。

关联附件默认显示在原事项下；按材料类型、重要程度或标签筛选时仍可单独找到。收支引用原账目 ID，金额和核销继续由原财务模块校验汇总，编辑任一视图不会新增第二笔钱。筛选支持重要程度、类型、标签和关联对象组合；当前界面开放前三种，关联对象过滤已提供查询契约。

## 接入新模块

1. 原生模块实现 `ResourceProvider`：声明唯一、建议带命名空间的资源种类，实现存在性、案件归属与生命周期校验。在 `ResourceRegistry` 装配时注册，冲突会明确拒绝。模块负责本体存储、删除/迁移清理及自身业务约束；共享注释存储保持不变。
2. 前端注册 `CaseModule`，声明模块 ID、时间轴类型、资源查找和投影函数。通过 `createCaseSystem(extra)` 加入模块，不修改时间轴合并和筛选算法。新资源的快照或查询传输由其原生模块提供，不接受前端声称的归属作为凭据。
3. 需要专属编辑器时，在 `CasePresentations` 注册详情适配器；缺少适配器时显示基础详情。类型名称与用户提示留在前端，本体校验留在原生模块。
4. 为归属、生命周期、备份恢复、日期含义和重复保存提供测试。注册机制面向随应用发布的受信模块，不装载下载脚本或任意远程代码。

## 已预留、尚未实现

- `DocumentEditorProvider`：读取草稿及按基础修订保存。后续实现必须拒绝陈旧修订、保留已提交版本。当前沿用已有文本创建/读取与系统文件能力，未交付 Word 排版、修订历史或新增自动保存编辑器。
- `DocumentTemplateProvider`：列出模板及版本，按案件字段生成独立草稿。缺失字段明确保留，模板更新不得修改已生成文书。当前未接入模板引擎。
- `CasePlanProvider`：任务起止日期、明确/预计日期及依赖，用于未来计划和甘特图。当前未实现依赖调度、甘特图或自动推算司法期限。

没有真实 provider 的能力不会被注册为可用服务，也不会显示成已工作的操作入口。

## 数据升级与验证

迁移 `008_case_system.sql` 增加注释、关联及清理触发器，原件、账目与既有资源 ID 保持不变。schema 7 升级前自动保存数据库副本；备份恢复支持 schema 3–8，旧应用拒绝打开 schema 8。

核心测试覆盖迁移副本、重启、案件恢复、备份恢复、跨案拒绝、重复请求、转案/删除清理与扩展解析器注册。前端测试覆盖模块注册、附件、筛选、日期语义、关系图及原账目引用；界面测试验证实际操作路径。
