# 案笺

2026-10-18 用户选定名称。案件为本，笺记工作：覆盖案件、日程、对象、材料和工作记录，保持个人本地软件的轻量感。

## 当前图标：1.8.6 银灰 8 / H / M

2026-11-17 用户确认将银灰组合字形更新到版本中。[正式母版](../../public/app-icon.png)采用石墨黑满版背景与银灰明暗渐变，H / M 共用笔画，外侧上下回环带出 8；右下收笔已融入下环，去掉此前独立的尾状装饰。配色参考用户提出的中性银灰方向，字形沿用案笺自己的组合设计。

母版是 1254×1254px 的不透明 PNG；iOS、Android、Windows 与 macOS 资源使用 `npm run icons:generate` 从同一[导出配置](../../public/app-icon.json)生成。应用内标识、欢迎页及网页图标同样使用该母版。平台标识、签名与安装升级路径保持兼容。

[实际导出尺寸对照](current/brand-1.8.6-sizes.png)在深浅表面按 128/64/60/40/32/24/16px 渲染，使用浏览器模拟圆角遮罩，不是手机桌面截图。60/64px 手机图标轮廓清楚，16/24px 下细部会减弱。母版和所有 iOS 导出尺寸已通过四边背景、透明度检查；Android 背景也来自同一配置。

`npm run icons:check` 检查母版、桌面主图及全部 iOS 尺寸的透明度和四边背景。iOS 装配也执行相同检查，拒绝透明边及白色衬边，再编码为无 Alpha 通道的 RGB，不再用白底补全透明空隙。实际编译图标继续做解码后像素比较；导出配置也统一 Android 自适应图标背景。签名测试包及可安装状态见[交付记录](../app-store/README.md)。

1.8.6（41.1）已签名上传并由独立 Apple 状态确认可内部测试。[签名包内实际解码图标](current/brand-1.8.6-compiled-ios.png)已查看，iPhone / iPad 图标与导出源像素误差均为 0，所有边缘不透明且保持声明的深色底；不把编译图标当作手机桌面实拍。与归档同源的完整应用和移动检查均已通过。

下方为旧品牌与本次设计迭代的历史记录。

1.1.4 按用户指定改为手写花体 HM：H 对应用户、M 对应其妻子的名字首字母。两个字母共用中间的倾斜笔画，以细连笔、较厚下行笔画和自然收笔组成一体的签名字形。按用户建议参考无边记的自由形状与层叠思路，采用黑色 `#08090b` 底层、不规则深灰内层，以及从青色 `#a4eee5`、蓝色 `#92bdf7` 到淡紫 `#c6a0ef` 的连续字形渐变。两个字母共用同一个渐变，不分别切色。参考来源为 [Apple 无边记](https://support.apple.com/guide/freeform/welcome/mac)，本图标保留自绘 HM 字形与轮廓。

字形由贝塞尔矢量路径直接绘制，不调用或分发额外手写字体。细线适当加重以适配小图标；[尺寸预览](current/brand-1.1.4.png)按实际 16、20、24、32、48px 渲染，小尺寸会减少书写细节，完整连笔在 24px 及以上更清楚。1.1.1 的几何 HM、AJ 与折页纸张均属于历史标志，普通文件图标继续使用统一的线性图标。

Windows 同时配置可执行文件资源图标、窗口图标和安装器快捷方式图标。稳定 AppUserModelID、安装目录注册标识保持兼容；不通过删除用户系统图标缓存掩盖配置问题。

安装包额外携带 branding/hm-mark.ico，快捷方式明确引用该文件，不再依赖 exe 的默认图标索引，避免沿用旧折页图标的快捷方式缓存。已在运行的旧程序仍使用其加载时的资源，需用户退出旧实例、安装并重新启动后显示新版图标；不会为换图标强制关闭用户正在工作的程序。

在线升级模式通常跳过新建快捷方式，因此安装模板还会仅为目标等于本安装 exe 的已有快捷方式更新 IconLocation，保留启动参数、工作目录及描述；不创建用户主动删除的入口，不改其他安装目录的链接，并只通知 Explorer 更新该链接。[隔离快捷方式测试](../../tests/native/shortcut-icons.ps1)使用临时链接验证这些规则，不安装到用户注册表或桌面。

本项目锁定的 Tauri 2.12 / tao 路径中，set_icon 仅设置 Windows ICON_SMALL。额外通过 [windows_icon.rs](../../src-tauri/src/platforms/desktop/windows_icon.rs) 在 UI 线程设置 ICON_BIG，持有独立 CopyIcon 副本并在退出时释放，避免任务栏仍显示通用文件图标。原生验收分别读取 exe 资源、窗口小图标和大图标，不只检查侧栏图片。

1.1.4 的[旧 HM 矢量源](current/brand-hm-1.1.4.svg)已归档；当时通过 Tauri icon 命令生成各平台资源。1.8.6 起使用上方 PNG 母版与统一导出配置。品牌调整保持应用标识、升级公钥、本地数据位置与旧安装注册标识兼容。

安装器沿用 Tauri 模板并固定旧注册表身份，见 [installer.nsi](../../src-tauri/windows/installer.nsi)。模板源码来自 [Tauri 官方仓库](https://github.com/tauri-apps/tauri/blob/dev/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi)，更新 CLI 时应核对上游模板变化。启动项也沿用原身份，避免改名造成重复自启动。

1.2.0 补充 Windows Shell 缓存同步：窗口图标与 Shell 任务栏分组图标是不同来源。启动时在独立 COM 线程中定向通知本安装 exe、branding/hm-mark.ico 及图标资源属于本安装的已存在快捷方式，保留全部快捷方式属性。仅在旧图像资源位置非空时使用其实际位置与索引更新图像项；资源解析返回的 Windows verbatim 路径先恢复普通 UTF-16 Shell 路径。后台状态分别报告窗口和缓存错误，不把 exe 资源检查当成实际任务栏验收。

1.8.4（37.2）在模拟器及签名构建初始化后，通过 [图标装配](../../scripts/ios-icons.mjs) 将每个 AppIcon 目录槽位替换为已提交的 iOS HM 素材，包含商店 1024px 图；随后按原白色底合成为不含 Alpha 通道的 RGB PNG。构建后使用[像素校验](../../scripts/verify-ios-icons.py)解码实际应用内的 PNG（包括 Apple CgBI 优化），与同尺寸品牌素材比较；与合成后的品牌像素超过编译容差即终止，不能进入上传。另导出实际编译图标供查看。已用旧版签名 IPA 验证此检查会拒绝默认图标；37.2 实际签名 IPA 的 iPhone/iPad 图标像素误差均为 0，未含透明像素，[Apple 独立状态](https://github.com/limushu/new_hm/actions/runs/44054213570)确认已可供内部测试安装，完整来源见[交付记录](../app-store/README.md)。

36.1 曾完成签名和图案像素核对，但 Apple 因大图标仍含 Alpha 通道拒绝上传；旧版 `altool` 即使报告失败仍返回退出码 0，不能以流程绿色或旧报告的 accepted 标记推断可安装。后续构建增加 RGB 格式断言，并要求明确 `UPLOAD SUCCEEDED` 且无验证失败，再查询 TestFlight 可安装状态。该次 36.1 不作为交付候选。

## 回到产品气质的三种方向

用户认为粗笔稿太夸张，钴蓝也不合适，并允许重新设计更符合案笺的图标。[三方向对照](current/brand-quiet-directions-2026-11-17.png)回到克制、中性表面与柔和强调色，以图形比例和留白建立辨识：

- **折笺**：墨绿色底、米白折纸带，折叠中隐含双环与 8 的意向。优先推荐此方向，兼顾纸笺语义与小尺寸下的轮廓辨识。
- **脉络**：石墨底、米白自由曲线与少量灰绿色收笔，延续连笔与事件关联的意向；细笔画仍需小尺寸验证。
- **案卷**：浅石色底、深色错叠纸页，使用简洁负形表达文档与归档。

当前是概念比较图，包含展示用系统圆角与中文方向名称，不能直接作为图标源文件。尚未替换正式品牌资源或安装包；后续按选定方向单独制作满版方形主图，并核对各平台实际资源。
