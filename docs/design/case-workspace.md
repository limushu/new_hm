# 案件工作空间 · 1.4

## 产品主线

案笺帮助个人律师把一项委托变成可跟进的工作：知道下一步、期限、等待事项、所需材料、已有成果及收费情况。档案可以简单使用，也可以逐步拆为多个并行的诉讼或非诉流程、阶段和任务。

本轮依据[六款律师软件的工作流调研](../research/lawyer-workflow-review-2026-10-18.md)形成实现。采用案件聚合、阶段组织工作、具体任务承接行动的方式，不引入强制闯关或大型律所审批。

## 四个页面的职责

| 页面 | 主要问题 | 操作与范围 |
| --- | --- | --- |
| 概况 | 全案正在做什么，下一步是什么 | 流程摘要、全案任务与等待、日程、委托身份、目标案情、人员、材料和费用摘要 |
| 办理 | 当前这部分工作怎样推进 | 选择流程及阶段，就地添加/编辑任务、安排、材料、记录、支出及收费节点 |
| 材料 | 哪份资料在哪里，被哪些工作使用 | 默认全案，按归档流程/阶段、文件夹和名称检索；工作关联支持一份材料多处引用 |
| 费用 | 应收条件和实收实支分别如何 | 整案约定、收费节点及实际收支分开；范围、列表、分类图及收支合计一致 |

一级页签只改变页面。浏览一个阶段不修改任何办理状态，也不会悄悄改变其他页面的范围。概况中的“当前关注”仍取案件保存的关注流程；浏览位置不抢占关注。

在阶段中点击“在材料库查看 / 查看相关费用”，资源页显示可清除的流程、阶段范围，并提供“返回办理”。材料自身的范围选项与显式范围同步；普通材料入口默认全案。整案收费约定始终明确标为“整案”，不假装属于阶段。资源页保留的筛选会继续显示。阶段删除后，对应筛选自动回到所属流程，记录不会被已不存在的阶段过滤掉。

## 关系图、阶段和历史各司其职

“流程关系”仅在办理页有多个流程时按需展开，说明承接与并行关系。不再重复出现在概况、材料或费用前方，也不充当资源筛选器。

阶段列表用于浏览；“调整阶段状态”明确修改待办理、当前办理、完成或跳过。阶段可重新打开，切换当前阶段不替用户完成其他阶段。已办结流程仍可浏览既有工作；恢复办理后再改变阶段状态。

流程资料、法院/法官、当事人及关联对象集中在“流程资料与当事人”；“事项与变更记录”单独折叠。关系、实际工作和历史不再混为同一张图。

## 单份事实与关联

任务、日程、材料、工作记录、账目分别保持自己的 ID。`work_links` 保存对流程和可选阶段的关联：

- 任务、日程、工作记录、账目各有一个工作归属。任务的等待对象和处理结果在 `task_work` 中补充。
- 材料保存一次，可以在多个阶段/流程使用，并填写“证据、草稿、成果、回执”等具体用途。归档目录是存储组织，工作引用是使用关系；两者不能互相冒充。
- 同一任务的截止日期直接投影到日历。日历可打开、修改这条任务，不另建事件。会议仍是独立日程，可从阶段新建或关联已有日程。
- 阶段内上传/原生拖入/录音的 `MaterialTarget.stageId` 在 Rust 归档时保存正式关联。材料和其他工作通过统一案件读取返回各视图。
- 删除阶段时，阶段引用改为未指定，任务、材料、日程、记录、账目及收费节点仍保留在所属流程。材料多个用途转为同一流程范围时允许并存，不因唯一性冲突阻止删除。解除用途关联不会删除原文件。

阶段提供可编辑的工作清单建议，用户预览并明确添加。只添加此阶段尚无的同名任务；重试、阶段切换、完成或重开不重复生成。清单是轻量辅助，不是自动推算法定期限的法律模板；本版未增加自定义清单库、工时计费或复杂触发器。

## 收费与款项

`fee_plans` 记录收费节点的名称、金额、相关流程/阶段、付款日期、条件和明确的条件确认。节点不强制覆盖所有阶段，也不强制与整案约定总额相等。

无附加付款条件的明确日期到期，或用户确认已满足收款条件，才计入“到期待收”。附加条件未确认时保持未到期，即使填写的参考日期已过；不能自动判断法律或合同条件。

`fee_allocations` 将实际收到的“律师费”收入核销到节点。同一收款可拆分，合计不得超过实收；节点核销合计不得超过该节点金额。核销不新增账目，修改已核销收款或降低约定金额时需要先核对现有核销。删除节点保留真实收款；删除账目会解除对应核销。阶段完成、重开或删除不会生成收款。

整案约定未填写与明确 0 元分开。迁移仅将历史正数金额视为已填写，旧 0 元不猜测；“修改约定”明确保存 0 元后可表达免费。整案未收不等于已经到期应收。

直接上传费用凭据仍采用复制归档和稳定上传 ID；凭据、金额及工作关联在同一 Rust 事务提交，失败清理新副本，取消不导入。旧原件和历史凭据保留。

## 迁移与边界

数据库 7 增加工作关联、任务补充、收费安排、核销及约定确认表和清理触发器。旧库先建立检查点备份，全部迁移和外键检查在一个事务完成。旧任务、日程、工作记录没有归属时继续属于案件；不从标题、时间、文件夹名或关注流程猜测阶段。旧账目不自动变成应收或分期。

备份恢复接受 3–7，旧完整备份恢复后迁移。生产规则位于 Rust `hm-core`，前端只负责操作与投影。保持本地、离线、安装模式和原更新签名体系；未增加云服务、自动收费、OCR 或工时系统。

## 视觉规则

沿用[字体映射](typography.md)的 30px 案件标题、18px 分区、15px 主阅读、14px 控件、13px 元信息。实际内容保持正文色，等待使用琥珀色，选中使用弱蓝底；不通过大量说明或整体放大/缩小字体解释业务。

同一功能占一整行，细节按需展开。单流程不重复绘制流程导航卡片；多个流程允许导航换行。小屏保持字号，按钮、任务和费用节点按内容换行，横向滚动限于关系图与时间表内部。
