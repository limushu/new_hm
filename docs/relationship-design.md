# 对象关系与信息页（1.4.1 更新）

本轮来自 2026-10-18 的评审：支持侧页外返回；法院、法官、案件建立可复用关系；参考 Obsidian 的反向链接和局部关系，优化字体。

## 对象资料优先与自由删除

点击对象名称默认打开“详情”，展示名称、类型、电话、地址和备注；未填写项目明确显示为空。反向关联、局部关系图为独立入口。目录的“关联案件”计数与程序内“查看法院关联”等明确指向关系的入口可直接打开关联页。点击关系中的另一个对象，先看该对象资料。

有关系的对象也能删除。确认框说明关联数量及影响；一个事务中解除该对象的全部案件身份和法院/法官关系，再删除对象。案件、材料、其他对象不受影响；程序中的法院和法官名称保留为历史文字。普通编辑案号不再运行旧数据回填，避免删掉对象后又自动生成。关联对象的自动回填仅在旧数据库迁移时执行。

案件删除入口常驻侧页右上角。看板卡片右上角也提供明确删除按钮，删除后可撤销；拖动仅用于调整状态。案件仍采用可恢复的软删除。

所有普通下拉菜单共用深灰面板、圆角、字重、悬停和选中标记，支持方向键、回车、Escape。菜单放在浏览器顶层，避免被弹窗边缘裁切。待办、日程、程序事件和收支共用可点选或直接输入的日期组件；待办使用独立的小型编辑弹窗，日期仍可留空，不自动创建日程。

## 关系模型

案件经办理程序连接法院与法官，保留一审、二审等各自历史。联系对象只有一个档案，身份按案件/程序保存；法院与法官的独立关联用于查找和候选筛选，可有多个法院关联，不冒充已确认的当前任职或任职时间。

选择程序的法院/法官后，同一事务写入联系关系和程序显示名称，不需要用户再填写一次或额外手动关联。选择新法院时清除该程序原法官，避免意外带入；若直接选择只有一个已关联法院的法官，可带出该法院。跨法院的法官须先补充对象关系。修改对象名称同步引用显示；编辑关联法院不会改写历史办理程序。

## 交互与字体

属性使用搜索选择器：显示已有对象、辅助联系方式/法院信息、键盘上下键/回车确认、Escape 只关候选；明确点击新建才建档。原位创建法院/法官后直接用于当前程序，姓名相同有提示但不擅自合并人员。

联系对象目录直接展示关联案件数；详情提供去重的反向案件、关联法院/法官，可沿链接来回查看。关系图展示案件、办理流程、法院、法官、个人和机构。1.4.1 参考 [Obsidian Graph view](https://help.obsidian.md/plugins/graph) 的点线画布、邻接高亮、分组颜色、全局与局部探索，采用以下明确规则：

- 联系对象页有全局入口，包含孤立对象；案件或对象的图默认局部 2 层，可选 1–3 层。
- 类型图例可开关节点；搜索名称或辅助信息只保留匹配节点和两端仍存在的连线。局部层级先按真实关联展开，再应用类型筛选。最多绘制 160 个节点，超限明确显示总数并提示缩小范围。
- 单击节点仅选中、突出邻居；下方显示真实的关系身份与可继续点击的关联对象。“打开对象详情 / 案件”才离开图；“以此为中心”才改变局部中心。双击可直接打开详情。
- 节点按直接邻居数改变大小，类型使用同一套主题颜色。初始力布局稳定可复现，名称自动避让；线上的身份文字收进选中详情，避免堆叠。
- 可拖动节点和空白画布，滚轮以光标为中心缩放；提供 + / −、Home 重置和方向键平移。移动仅改变当前视图，不修改任何业务关系，也不永久固定对象。
- 同一对节点的多个身份合并为一条连接并列出全部身份。委托人即使尚未开始办理，也通过案件当事人记录进入图与反向案件列表；回收站案件不进入图。
- 展开画布、手机换行、深浅主题均共用交互，图是查找关系的辅助入口，案件工作仍在办理页完成。

侧页外覆盖透明返回区域，先让焦点字段提交，再等待保存完成，不触发后方卡片操作；弹窗和候选选择仍在各自交互层。字体优先使用系统 UI 字体，补齐中文回退，统一正文行距和 400/500/600 字重，避免缺失字体及不可用字重造成标题过粗。

## 迁移与边界

004_contact_relations.sql 将数据库升级到 4，迁移前保存独立副本。旧程序的法院/法官文字按唯一对象匹配，缺少时建档复用；重名或多个旧关联有歧义则保留原文，不擅自挑选一个。旧 1.0.0 的版本 3 完整备份仍可恢复并迁移。生产数据不用于开发测试。

核心回归覆盖复用、角色归属、历史程序、名称同步、无效关系回滚、旧库歧义、旧备份恢复；界面覆盖返回、搜索选择、法院筛选法官、反向关联、图导航和手机宽度。

独立绿色目录的单实例锁按工作区隔离，避免与已打开的安装版相互转发；默认安装版标识及业务数据目录不变。原生验证只使用隔离虚构工作区，不关闭或迁移用户正在运行的旧版。
